# Sekiban DCB 10.24.2

- バージョン: `10.24.2`。DCB ライブラリは 26 パッケージです。net9.0 と net10.0 を対象とします。
- マルチプロジェクションのスナップショットの復元と保存の修正です（[#1382](https://github.com/J-Tech-Japan/Sekiban/issues/1382)）。公開 API と依存パッケージは 10.24.1 から変わっていません。Orleans は 10.4.2 のままです。
- DCB のイベントデータの移行は不要です。

## 修正

- スナップショットの復元がキャンセルされても、全件の再生にならないようにしました。以前は、保存済みのマルチプロジェクションのスナップショットの復元がキャンセルされると、grain はスナップショットが壊れている場合と同じに扱っていました。整合性の watermark をリセットし、保存済みのスナップショットを無効にするため、次の activation ではすべてのイベントを再生していました。復元は、Orleans の activation のタイムアウト（既定で 30 秒）より長くかかったとき（たとえば起動したばかりの silo での大きなスナップショット）や、再起動中にストレージへの要求がキャンセルされたときにキャンセルされます。今は、その activation が保存済みの状態を変えずに失敗し、次の activation が保存済みのスナップショットをもう一度復元します。キャンセル以外の復元の失敗は、これまでどおり全件の再生になります。
- 大きなスナップショットの復元が activation のタイムアウトより長くかかる場合、今は全件の再生にはならず、activation が毎回失敗します。grain は、activation のタイムアウトを示す警告をログに出します。復元が終わるように、silo の設定でタイムアウトを延ばしてください。たとえば `siloBuilder.Configure<GrainCollectionOptions>(options => options.ActivationTimeout = TimeSpan.FromMinutes(5))` のようにします。
- 保存しない場合には、スナップショットの payload をアップロードしないようにしました。以前は、保存済みのスナップショットの方が grain より進んでいるあいだ（たとえば再生中）、保存のたびに offload する payload の Blob をアップロードしてから保存を取りやめていたので、そのたびに参照されない Blob が残りました。今は、先に保存できるかを確かめ、保存しない場合はスナップショットを作りません。アップロードの後で保存が失敗したり、ほかの書き手が先に保存したりした場合は、Blob が残ることがあります。ライブラリは Blob を削除しません。以前のバージョンで残った Blob は、アプリ側の仕組みで削除してください。
- スナップショットを無効にした後の全件の再生（復元の失敗、作り直し、fault のリセットの後や、無効にしたスナップショットを再起動で見つけたとき）でも、途中の checkpoint を保存するようにしました。以前は、無効にしたスナップショットを残すストア（Cosmos DB、PostgreSQL、SQLite、DynamoDB、in-memory）では、その古いイベント数を再生が超えるまで保存がすべて止まっていたので、再生中に再起動すると、また 0 から再生していました。今は、再生中も通常の間隔で保存します。これにより、無効にしたスナップショットのイベント数が、イベントストアから再生できる数より多い場合（たとえばイベントストアをリセットした後）も直ります。次の activation が作り直した checkpoint を保存するので、トラブルシューティングガイドにある手作業の復旧は、以前のバージョンでだけ必要です。
- 別の書き手がフルリビルドのために checkpoint を無効にしたことで保存を拒否された grain が、それまでの状態を保存しないようにしました。以前は、checkpoint の世代管理に対応したストア（Cosmos DB、PostgreSQL、SQLite、DynamoDB、in-memory）で、たとえば複数のクラスタが 1 つのストアを共有しているとき、その grain の次の保存（タイマー、catch-up の後、deactivate のとき）が、その古い状態を checkpoint として保存することがありました。その checkpoint にはリビルドで含めるはずのイベントが含まれず、その後の activation がそれを復元していました。今は、その grain は保存をやめ、次のクエリで、実行中のフルリビルドと同じくイベントストアからすべてのイベントを再生します。保存するのは再生した状態だけです。

## 更新するとき

10.24.0 より前のバージョンから更新する場合は、先に 10.24.0 のリリースノートを読んでください。Orleans 10.4.2 では、クラスタ全体を同時に更新する必要があります。

## テンプレート

10.24.2 のテンプレートは、ライブラリの後に、別途リリースします。10.24.1 のテンプレートは公開していません。
