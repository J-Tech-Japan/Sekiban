# DCB templates 10.23.1

The five starter templates use the public DCB packages and improve local usability and production defaults.

- Decider reservation and approval projectors and room states now copy their inputs, including touched day-index buckets. This deliberately gives up the throughput optimization from #997 to demonstrate immutable projection inputs.
- Demo users, the development JWT key, debug and projection maintenance routes, test-data generation and any-origin CORS are limited to Development. Next.js gates demo controls on the server and rejects test-data procedures outside development. JWT keys are validated at startup; deployments must supply a signing key from a secret store and can bootstrap the first administrator through configuration. Identity schema and roles are still initialized in every environment.
- The Blazor login page and pooled authentication client are removed; registration and login use Next.js. Direct API cookie authentication now uses the Identity application cookie, while bearer authentication remains available.
- Materialized views, stores, Orleans projection grain keys and the three storage-aware CLIs share one explicit application identity (`Sekiban:ServiceId`). Unsafe-window reads use the same event store. **For projects generated by an earlier template, do not change the existing ServiceId: their data lives under `default`.**
- Retryable projection catch-up and rebuild failures return 503 with `Retry-After`. Malformed JSON returns 400 in the WithoutResult templates. Bounded first-query waiting and other prerequisite-dependent opt-ins remain disabled.
- WithoutResult honours configured Azure Queue/Event Hub streams, persistent PubSub storage and App Service/Container Apps silo endpoints. Dockerfiles restore with the imported version props, use stable .NET images and correct project names. LocalStack is deliberately pinned to a token-free local image. Deprecated OpenAPI calls, stale comments and unsupported AWS Cosmos settings are removed.
- Generated solutions now include local-run and production guidance. AWS documentation correctly describes DynamoDB, the list-only CLI, memory streams and grain storage, restart limitations, and RDS membership/reminders. The shipped infrastructure does not provision JWT secrets.

Readiness improvements, the DynamoDB table-creation race, real cloud deployment verification and multi-silo verification are outside this template update.
